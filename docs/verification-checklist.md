# 検証チェックリスト

本番デプロイ前の手動確認。コードから組み直したもの(2026-08-09 時点)。

各項目は **操作 → 期待される結果** の形。期待値はすべて実装を読んで確認した実際の挙動で、
「こうあるべき」ではなく「こう作ってある」。ずれていたらそれは不具合か、仕様の記録漏れ。

### A-1b アプリ内ブラウザ(LINE / Instagram)

学生の大半はここから来る。**ポップアップは WebView では最後まで通らない**ので、
UA を見てリダイレクトに切り替えている。UA を偽装すれば PC で確認できる:

DevTools → `⋮` → More tools → **Network conditions** → *Use browser default*
のチェックを外して UA を貼る → **リロード**(判定は mount 時)。

```
LINE (iOS)   Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Mobile/15E148 Safari/604.1 Line/14.2.0
Instagram    Mozilla/5.0 (Linux; Android 13; SM-S918B Build/TP1A; wv) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/120.0.0.0 Mobile Safari/537.36 Instagram 302.0.0.23.113 Android
通常 Chrome   Mozilla/5.0 (Linux; Android 13; Pixel 7) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Mobile Safari/537.36
```

- [ ] A-1b-1 **LINE の UA** → ログイン画面の下に金色のパネル。
      「LINE 内のブラウザで開いています。…Safari / Chrome で開いてから…」
- [ ] A-1b-2 同意して押す → **ポップアップが出ず、ページごと**
      `…firebaseapp.com/__/auth/handler` → Google に遷移する
- [ ] A-1b-3 **Instagram の UA** でも同じ(パネルは「Instagram 内の…」)
- [ ] A-1b-4 **通常 Chrome の UA** → パネルは地味な灰色の一行。
      押すと**ポップアップが開き**、ページは `/login` のまま
- [ ] A-1b-5 「リンクをコピー」→ ラベルが「コピーしました」に変わり、
      2〜3 秒で戻る。クリップボードに現在の URL が入っている

> **実機が本命。** リダイレクト方式は `authDomain` が別オリジンなので、
> サードパーティ Cookie を切っているブラウザでは最後まで通らないことがある。
> **自分の LINE にプレビュー URL を送ってタップし、サインインが完了するか**を
> 必ず一度確認する。ここだけは UA 偽装では分からない。

トーンは 2 つだけ: **じっくり**(counselor)/ **ストレート**(karakuchi)。

- [ ] `/chat` のヘッダーにトーンのピルが出ている。**チャット画面にだけ**出る

- [ ] **いま話している方を選ぶ → メニューが閉じるだけ。確認ダイアログも新規セッションも出ない**
- [ ] もう片方を選ぶ → 「〇〇に切り替えますか?」ダイアログ。本文に

- [ ] トーンによって AI の話し方が実際に違う(じっくり = 受け止めてから 1 つ聞く /

## C. 自動抽出(トースト + 重複なし)

抽出が走る条件は 4 つ。**画面下タブでの普通の移動では走らない**ことに注意。

| 引き金 | 必要な新規発言数 |
| --- | --- |
| トーン切替の確定 | 2 |
| ヘッダーの ＋(新しい壁打ち) | 2 |
| ドロワーで別セッションを選ぶ | 2 |
| タブ/アプリに**戻ってきた**とき | 6 |

- [ ] C-1 具体的な出来事を 2 往復以上話してから ＋ を押す → 数秒後に
      **金色のトースト「「{タイトル}」を自分史に追加しました」**
- [ ] C-2 トーストは**画面下・タブバーの上**に出て、**約 4 秒で自動的に消える**
- [ ] C-3 `/jibunshi` を開く → そのエピソードがカードとして存在する
- [ ] C-4 **AI の最初の 1 通しか無い新品のセッションで ＋ を押す → トーストは出ない**
      (学生の発言が 1 つも無いと抽出しない)
- [ ] C-5 抽出するものが無かったとき(雑談だけ等)も**無言**。「何もありませんでした」
      とは言わない
- [ ] C-6 **重複しない**: 同じ壁打ちの中で同じ出来事をもう一度語ってから抽出 →
      **新しいカードが増えず、既存のカードが更新される**
      (トーストが「追加しました」ではなく**「更新しました」**になる)
- [ ] C-7 タブを別のタブに移して戻る → 新規 6 発言以上あれば走り、5 以下なら走らない
- [ ] C-8 オフラインで抽出を走らせる → 赤いトースト「自分史への保存に失敗しました。
      次に開いたときにもう一度試します。」
- [ ] C-9 C-8 のあとオンラインに戻して同じセッションでもう一度引き金を引く →
      **取りこぼしが回収される**(失敗した分が消えていない)
- [ ] C-10 抽出が走っても**履歴の並び順が変わらない**(`updatedAt` を触らないため)

> **既知の範囲**: 重複判定は**同じセッション内のエピソードとしか比べない**。
> 別の壁打ちで同じ話をすると 2 枚目のカードができる。仕様として許容するか、
> 直すかは判断が必要(→ 末尾「判断がいる点」)。

## F. 設定の保持(別ブラウザ確認)

**保存先がここの本質:**

| 設定 | 保存先 | 別ブラウザに引き継がれるか |
| --- | --- | --- |
| 文字サイズ | Firestore `users/{uid}/settings/app` | **はい** |
| テーマ | Firestore(同上) | **はい** |
| 言語 | どこにも保存しない | — (そもそも設定ではない) |

`localStorage` の `sc-settings` は**起動時のちらつき防止のミラー**であって記録ではない。

- [ ] F-1 文字サイズを「大」に変える → **その場ですぐ**反映される(保存待ちが無い)
- [ ] F-2 設定画面の**「この一文だけは大きさが変わりません。」だけは 12px 固定**で、
      他のサンプル文は拡大縮小する
- [ ] F-3 テーマを「ダーク」に → 即反映
- [ ] F-4 テーマを「端末に合わせる」に → OS のダークモードを切り替えると追随する
- [ ] F-5 **別ブラウザ(またはシークレットウィンドウ)で同じアカウントにサインイン
      → 文字サイズとテーマが引き継がれている**
- [ ] F-6 Firestore Console で `users/{uid}/settings/app` に `fontSize` と `theme` が
      入っていることを目視
- [ ] F-7 **言語行**: 「日本語」が選択済み。**「English」は押しても何も起きない**
      (点線枠 + "Coming soon" の無効表示。仕様)
- [ ] F-8 サインアウトしてログイン画面を見る → **その端末で最後に使われた見た目**が
      効いている(ミラーが効く場面)

> **確認しておきたい挙動**: Firestore の設定読み取りが失敗/タイムアウトすると、

## G. 日次上限

- 上限: `DAILY_MESSAGE_LIMIT`(未設定なら **50**)
- カウンタ: Firestore **`users/{uid}/usage/{YYYY-MM-DD}`** の `count`。日付は**日本時間**
- **AI の最初の 1 通は数えない**

50 回送るのは現実的ではないので、**`apps/web/.env.local` に一時的に
`DAILY_MESSAGE_LIMIT=2` を置いて dev サーバを再起動**して確認する。
確認が終わったら消すこと(本番値は `apphosting.yaml` 側なので影響しない)。

- [ ] G-1 上限まで送る → 次の送信で会話の中に赤い箱

## J. 壁打ちの削除

**この節の主役は「消えないこと」のほう。**壁打ち=過程、自分史=資産という設計なので、
記録を消してもエピソードは 1 件も減ってはいけない。

準備: エピソードが 1 件以上抽出済みのセッション X を用意する(C の手順で作れる)。
削除前に **自分史のカード枚数を数えておく**。

- [ ] J-1 ドロワー / 履歴画面 / PC のサイドバー の**3 か所すべて**で、各行の右端に
      ゴミ箱アイコンが出ている。行のタイトルと重なっていない
- [ ] J-2 ゴミ箱をタップ → 行は開かず、**確認ダイアログだけが出る**
      (「この壁打ちの記録を削除しますか?」+「抽出済みの自分史エピソードは削除されません。」)
- [ ] J-3 「キャンセル」/ 背景タップ / Escape のどれでも閉じ、**何も消えていない**
- [ ] J-4 「削除する」→ 実行中は両ボタンが無効(「削除しています…」)。完了後に
      **一覧からその行が消え**、「壁打ちの記録を削除しました」のトーストが出る
- [ ] J-5 **自分史のカード枚数が削除前と同じ**。年表からも消えていない ← 最重要
- [ ] J-6 削除したセッションから抽出されたカードを開く →
      **「元の対話を見る」が出ていない**(存在するセッションのカードでは出る)
- [ ] J-7 **いま開いている壁打ちを削除** → ドロワーが閉じ、`/chat` に移る
      (一番新しい開いている壁打ち、無ければ新規)。**戻るボタンで消えた会話に戻らない**
- [ ] J-8 削除した直後に別の画面へ移動しても、**抽出のトーストが後から出てこない**
      (消したセッションの抽出が走っていない)
- [ ] J-9 Firebase Console で `users/{uid}/sessions/{X}` と配下の `messages` が

- [ ] J-10 長い会話(50 往復以上)でも削除しきれる。`messages` が残っていない
- [ ] J-11 機内モードにして「削除する」→ ダイアログが開いたまま
      「削除できませんでした。…」が出て、**もう一度押せる**

> 他人のセッションを消せないことは手ではなく `npm run check:rules` で見る
> (「他人の壁打ちは削除できない」「他人のメッセージは削除できない」)。

## 判断がいる点(不具合ではなく、決めていないこと)

チェックリストとは別。潰すか、記録して次に回すかを決める。

1. **オンボーディングの保存に締め切りが無い** — `saveOnboarding`
   (`lib/firebase/users.ts:94`)だけが `withTimeout` を通っていない。Firestore に
   届かないとき、ボタンが「保存しています…」のまま無期限に止まり、エラーも出ない。
   アプリ内の他のすべての読み書きには 10 秒の締め切りがある。**ここだけ例外。**
2. **設定が 10 秒後に既定値へ戻る**(F の注記)— ミラーで正しく出たあと、
   Firestore の読み取りが失敗すると既定値で上書きされる。
   「読めなかったら今出ているものを維持する」ほうが素直かもしれない。
3. **年表の編集・削除の失敗が表示されない** — 楽観更新のみで、Firestore への書き込みが
   落ちても画面は成功したように見える。リロードで戻る。
4. **重複判定がセッションをまたがない**(C の注記)。
5. **`unauthorized` が英語のまま学生に出る** — `app/api/chat/route.ts:68`。
   トークンが切れた状態で送信すると、赤い箱に生の英単語が出る。
   他のエラーはすべて日本語の一文になっている。
